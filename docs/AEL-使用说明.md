# AEL 使用说明

> AEL（AI Engineering Ledger）是一个本地优先的 AI 编码治理工作台。它不是大模型本身，而是把 Agent 的运行、记忆复用、安全裁决和过程证据放在同一个任务里管理。

## 1. 你需要准备什么

- Windows 10/11（当前发布版本主要面向 Windows）。
- 至少安装一个 Agent CLI，例如 Codex、Claude Code、Gemini CLI 或 OpenCode，并确保命令已经加入 `PATH`。
- 如果要让 Agent 修改代码，准备好项目目录和 Git 仓库。AEL 可以记录分支、提交和代码来源，但不会替你创建远程仓库。
- Provider/MCP 由目标 Agent 或外部配置工具管理；AEL 的「集成」页只读取状态，不把连接配置作为主流程。

AEL 的默认本地数据目录是 `%USERPROFILE%\.ael\`，包括 SQLite 数据库、备份、交接包、Review Brief、记忆和安全策略。数据默认不上传到 AEL 服务。

## 2. 启动 AEL

### 直接使用已构建版本

双击以下文件即可启动：

```text
D:\desktop\智创OPC源码\ael3\src-tauri\target\release\ael3.exe
```

### 从源码启动

在项目目录执行：

```powershell
cd D:\desktop\智创OPC源码\ael3
pnpm install --frozen-lockfile
pnpm tauri dev
```

只想预览前端界面（使用浏览器 mock 数据）可以执行：

```powershell
pnpm dev
```

## 3. 第一次使用：从一个任务开始

1. 点击左上角菜单，选择「新建任务」。侧边栏里的大按钮是唯一的新建任务入口，不需要再找第二个同名菜单项。
2. 填写任务名称、目标、验收条件和项目路径。目标应描述“要解决什么”和“不能破坏什么”，不要只写“帮我改一下”。
3. 选择分支和 Agent（也可以留到启动工作台时再选）。
4. 点击「创建任务」，AEL 会先做记忆预览和 Failure Guard 检查。
5. 在预览窗口确认要带入的已验证记忆、失败护栏和上下文预算，再点击「确认并开始」。

任务创建后会打开该任务的详情。要运行 Agent，从侧边栏进入「工作台」并在「绑定任务」中选择它。

## 4. 运行 Agent 的标准流程

1. 打开「工作台」，在「绑定任务」中选择任务。
2. 选择一个已检测到的 Agent，确认工作目录。目录通常填写项目根目录。
3. 点击「启动 Agent」。AEL 会将任务目标、相关记忆和安全约束生成启动上下文。
4. Agent 的输出会显示在终端区域，并按事件写入当前任务的证据链。
5. 如果出现“命令需要确认”，先阅读命令和触发规则，再选择「放行」或「阻止」。不要为了让流程继续而盲目放行。
6. 需要继续指导时，在底部输入框发送一行；需要结束会话时点击停止按钮。

侧边栏中的「最近任务」按更新时间排序。任务较多时，在侧边栏中直接滚动即可继续查看；完整任务与证据可从「证据 → 任务与证据」进入。

## 5. 任务完成后的记忆沉淀

推荐每个任务都走完以下闭环：

```text
目标 → 运行 Agent → 记录事件 → 验证 → Review → 收尾 → 记忆复用
```

- 「证据 → 任务与证据」：查看目标、状态、Agent 会话和完整证据链。
- 「证据 → Review Brief」：生成一页 Review Brief，集中查看目标、决策、拦截、验证和风险。
- 「收尾任务」：任务验证通过后执行收尾，AEL 才会生成可复用的 Skill 草案；失败任务会形成 Failure 记录。
- 「记忆」：审阅草案，确认后启用。错误或无关记忆可以停用/遗忘；停用后不会再进入新任务召回，但历史来源仍保留。
- 「本次记忆」：工作台右侧显示当前任务实际匹配到的记忆及其来源，不是把整个历史数据库都塞给 Agent。

记忆是否被复用取决于目标相似度、标签、验证状态和保鲜期。模型或 Agent 发生变化时，旧 Skill 可能被标记为“待重验”，应先重新验证再继续启用。

## 6. 多 Agent、Provider 与 MCP

打开「集成」：

- 页面显示本机 Agent、ACP → PTY 运行通道、固定配置目标以及外部工具状态。
- AEL 不复制维护 Provider/MCP 深度配置；需要修改时使用目标 Agent 的原生工具。
- 已确认的 Skill 可从「记忆」导出为标准 `SKILL.md`；本机存在 skills CLI 时由它负责分发，否则保留可移植文件。

AEL 负责统一管理连接层和证据层；每个 Agent 的具体模型能力、登录状态、额度和 CLI 行为仍由对应工具决定。

## 7. 接手、决策与代码来源

- 「设置 → 交接包」：选择任务并导出 AHP 接手包。交接包包含任务、事件、相关记忆、失败记录、决策和可用证据。
- 把交接包导入另一台机器后，打开生成的接手 Prompt，先阅读约束和此前的坑，再继续工作。
- 「决策」：把任务中的 decision 事件编译成 ADR，记录为什么选择某种方案。
- 「来源链」：扫描带有 `AEL-Task:` trailer 的提交，把代码行关联回任务、会话和人工裁决。

## 8. 常见问题

### Agent 显示 Missing

在 PowerShell 执行对应 CLI 的 `--version`，确认命令可用且已加入 `PATH`。修改 PATH 后需要重启 AEL。

### 启动时没有 Agent 输出

确认任务已绑定、工作目录存在且 CLI 可以在该目录独立启动。先在「工作台」选择任务，再点击「启动 Agent」，不要只创建任务而期待 Agent 自动运行。

### 仍然感觉界面卡住

确认运行的是最新的 `target\release\ael.exe`，并关闭旧进程后重新启动。高频输出会被后台队列和前端批处理；如果看到输出过载提示，应降低 Agent 日志级别或缩小任务范围。

### 记忆没有被召回

检查记忆是否为 `active`、是否通过验证、目标描述是否足够具体。打开新任务的记忆预览，可以看到召回理由和失败护栏，而不是猜测系统是否注入成功。

### 如何备份或迁移

在「设置」中执行立即备份，或导出任务交接包。不要直接删除 `%USERPROFILE%\.ael\ael.db`；需要清理数据时先导出并保留备份。
