# AEL 2.0 创新升级方案
## 从「Agent 经验层」到「AI 编码治理层」—— 原有内核不变,长出四个行业级出口

> **一句话定位**
> AEL 是本地优先的 AI 编码治理层:**黑匣子**(证据溯源)+ **海关**(运行时网关)+ **账本**(经验与责任资产)。
> 让 AI 写的每一行代码 **可信 · 可控 · 可追责 · 可理解**。

---

## 0. 为什么是现在:行业拐点已经出现

AI 编码的行业难题已经从「生成不够快」切换为「生成之后全面失控」:

| 难题 | 行业现状 | 来源 |
|---|---|---|
| 信任危机 | 96% 的开发者无法完全信任 AI 生成的代码——不是质量不行,而是故障责任由人和企业承担 | Sonar 2026 开发者调研 |
| 审核塌方 | AI 约 5 分钟生成 1000 行代码,人工审核同等代码约需 40 分钟,产能远超审核上限 | 虎嗅《AI 太会写代码,人类已经审不过来了》 |
| 运行失控 | 54% 受访企业已出现确认的 Agent 安全事件或未遂事件;69% 存在 Agent 凭证共享 | VentureBeat 企业调研 |
| 债务清算 | AI Coding 赛道进入「技术债清算整合期」,代码治理与护栏工具被判断为企业 IT 预算最大刚需 | 2026 全球 AI Coding 产业研判 |
| 理解债 | 「氛围编码两年攒下的烂摊子」引爆社区;开源项目被无人理解的 AI 贡献淹没 | 开发者社区 / Godot 维护者 |

**关键判断:治理所需要的东西——完整执行链路、错误知识库、决策记录——恰好是 AEL 1.0 已经在做的。**
业界共识的审计链路是 `user → agent → session → tool → 策略裁决 → 结果`,而 AEL 的
`task → agent_session → terminal_chunks → task_events → guard 判定 → 验证` 就是它的本地实现雏形。

## 1. 不丢的底座:1.0 核心创意全部保留,并且升职

| 1.0 原有创意 | 原有价值 | 在 2.0 中的新角色 |
|---|---|---|
| PTY 执行层(启停 / 输入 / transcript 落库) | 把 Agent 拉起来跑 | **治理的物理抓手**:天然的策略执行点(网关位置) |
| 证据链 `task_events`(step/error/fix/decision/verify) | 过程留痕 | **治理的数据源**:审计链路、Review Brief、行级溯源的原料 |
| Failure Guard(签名归一化 → 约束注入) | 同一个错不再犯 | 升级为**三段式运行时护栏**(事前预报 / 事中裁决 / 事后沉淀) |
| finalize(证据 → draft Skill/Failure,人工确认) | 经验沉淀 | 升级为**编译器**:同一条证据链编译出 Brief / ADR / Skill 三种产物 |
| handover.zip(零上下文接手) | 换人续做 | 升级为**溯源与责任凭证** + 开放交换标准(AHP) |
| 工作区锁 / 多 Agent 会话 | 防踩踏 | **Agent 编队安全基元**(并行赛马与路由的前提) |
| 两条成功标准 | 产品北极星 | 保留,并扩展为四条(见 §6) |

> 原则:**2.0 不做替换,只做接线。** 经验层是发动机,治理层是接在发动机上的四个输出端口。

## 3. 四大行业难题 × 四个出口

### 3.1 出口一:Review Brief —— 把「审代码」变成「审证据」

- **难题**:生成 5 分钟 / 审核 40 分钟,审核是全行业最大瓶颈;企业选型必问「谁发起、AI 建议了什么、人接受了什么」。
- **解法**:finalize 增加 Brief 编译目标。每次任务自动产出一页审阅摘要:
  任务目标 → 关键决策及理由(decision 事件)→ 已拦截/已修复错误(error+fix 事件)→
  验证证据(verify 事件:测试是否真的跑过、结果如何)→ 风险标注(未验证路径)。
- **配套**:`ael brief <task>` CLI;git hook / PR bot——**AI 生成的提交必须附带证据包方可合入**。
  开源场景反向输出:带证据链的贡献 = 「我理解我交的东西」的可验证证明,直接回应 Godot/cURL 式的贡献淹没危机。
- **复用/新增**:复用 task_events、finalize;新增 brief 模板引擎 + hook 脚本(改动量:小)。
- **验收**:千行级 AI diff 的人工审阅中位时间 ≤ 5 分钟。

### 3.2 出口二:Agent Blame —— 行级代码溯源账本

- **难题**:git blame 只能追到「人」;96% 不信任的根源是责任无法归位——出了事故,分不清「AI 建议错了」还是「人确认错了」。
- **解法**:提交时写入 commit trailer(`AEL-Task: T-0417`),证据链按 diff hunk / 行号锚定。
  任意一行 AI 代码 → 3 秒回放决策现场:哪次任务、哪个 Agent、哪个模型版本、基于哪条 decision、人工确认记录。
- **责任切分**:证据链天然区分「AI 提议」与「人类确认」两类事件——事故复盘与合规审计共用同一份账本。
- **复用/新增**:复用 task_events、handover manifest;新增 trailer 写入 + 行锚定索引(改动量:中,约一周量级)。
- **验收**:任意 AI 生成行,3 秒内定位到完整决策上下文。

### 3.3 出口三:本地 Agent 网关 —— Failure Guard 升级为「海关」

- **难题**:政企落地四大困境「执行不可信、隐私泄露、Token 失控、生态割裂」;安全规则写进 prompt 会在长任务后半段被模型遗忘。
- **核心洞察**:**规则会被模型遗忘,但不会被网关遗忘**——运行时裁决必须在模型之外,而 AEL 的 PTY 恰好坐在 Agent 与 Shell 之间。
- **解法**:Failure Guard 三段式:
  1. **事前 · 风险预报(pre-mortem)**:启动前用失败库相似度生成「本次最可能踩的坑」并注入(1.0 已有,保留);
  2. **事中 · 运行时裁决**:签名匹配在 terminal_chunks 流上实时运行;策略引擎(`policy.toml`)拦截危险命令
     (破坏性删除 / 高危 SQL / 密钥出站探测 / 预算熔断——复用已有 token 估算),高危操作走人工确认;
     transcript 落库前自动脱敏;
  3. **事后 · 沉淀(1.0 已有,保留)**:新错误签名入库,闭环回到经验层。
- **复用/新增**:复用 PTY、签名引擎、token 估算;新增策略引擎 + 审批 UI(改动量:中)。
- **验收**:内置策略集对危险命令样本的拦截率;误拦率低于阈值(沿用「宁可漏报」哲学,阈值可调)。

### 3.4 出口四:活文档 —— 理解债的偿还机器

- **难题**:vibe coding 烂摊子的根因不是代码差,是 **why 全部丢失**;半年后无人知道 AI 为什么这么写。
- **解法**:decision 事件在 finalize 时自动编译为 ADR(架构决策记录),同步更新 CLAUDE.md 约定区,
  并在关键文件留下注释锚点(`// AEL:T-0417 决策见 adr/0023`)。代码被生产的同时,「为什么」被同步固化。
- **复用/新增**:复用 decision 事件、skills 目录;新增 ADR 模板 + 锚点写入(改动量:小)。
- **验收**:新成员仅凭仓库内 ADR/锚点即可回答「这个模块为什么这样设计」。

### 3.5 横向机制(上一轮创新观点,全部并入 2.0)

- **经验保鲜期**:每条 Skill/Failure 绑定产生时的模型与工具版本;检测到模型换代 → 自动降级「待重验」,由后续成败计数决定复活或淘汰。把「AI 发展太快」从威胁变成独有功能。
- **经验驱动智能路由 + 赛马评测**:skill_usages 成败数据 = 本地私有 Agent 评测榜;新任务自动推荐最擅长的 Agent;git worktree 并行升级为双 Agent 赛马 + 证据链评分,结果反哺路由。
- **MCP 双形态**:经验层同时暴露为 MCP Server(`query_skills / check_failures / record_decision / export_handover`),被原生 CLI 在会话内调用——原生功能越强,调用你的场景越多。
- **AHP 开放标准**:handover.zip 抽为公开规范(Agent Handover Protocol),接手方扩展到「下一代模型」——模型升级时长任务无损迁移续跑。

## 4. 边界与生态:不和 cc-switch 抢赛道

| 层 | 代表 | 管什么 | AEL 态度 |
|---|---|---|---|
| 配置态 | cc-switch | Provider / Key / MCP / Skills 安装 | **兼容并外包**:读取其配置,化竞品为上游 |
| 会话态 | 原生 CLI(Claude Code / Codex…) | 对话、原生记忆、子代理 | **被调用**:以 MCP 形态成为它们的记忆外挂 |
| 执行态 + 治理态 | **AEL** | 证据、护栏、溯源、经验资产 | **独占**:唯一同时握有执行链路与经验库的位置 |

一句话:**cc-switch 管钥匙,原生 CLI 管对话,AEL 管记忆、护栏和账本。钥匙人人一样,记忆与责任独一无二。**

## 6. 成功标准:两条老的,两条新的

1. **同一个错误,第二次不再犯**(1.0 保留)
2. **换 Agent 接手,不必重讲上下文**(1.0 保留)
3. **千行 AI diff,审阅 ≤ 5 分钟**(新:回应审核塌方)
4. **任意一行 AI 代码,3 秒追到决策现场**(新:回应责任真空)

## 7. 一页话术(README / 评委版)

> AI 干活会越来越便宜,工具切换会彻底免费,但有三样东西不会被下一个模型覆盖:
> 你的项目**踩过哪些坑**、**为什么做了这些决策**、**每一行代码该由谁负责**。
> AEL 把这三样东西做成本地优先的资产:证据链是黑匣子,运行时网关是海关,经验与溯源是账本。
> 1.0 让「同一个错不再犯、换人不重讲上下文」;2.0 在同一个内核上,让整个行业「审得过来、追得到责、管得住手、读得懂为什么」。
