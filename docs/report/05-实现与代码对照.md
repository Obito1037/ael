## 5.2 功能与代码对照

演示时被问“这个功能由哪段代码实现”，按下表回答。路径相对 `src-tauri/src/`（后端）和 `src/`（前端）。

| 功能 | 入口 | 关键代码 | 做了什么 |
|---|---|---|---|
| 新建任务 | `views/Overview.tsx` | `commands/task.rs` → `db/task.rs` `create_task` | 写入任务，创建前预览记忆 |
| 启动前护栏 | `views/Overview.tsx` | `engine/guard.rs` `check_failure_guard` | 匹配历史失败，生成约束 |
| 启动上下文 | `views/Console.tsx` `launch` | `agent/context.rs` | 拼接目标、约束、记忆和交接内容 |
| 启动 Agent | `views/Console.tsx` `launch` | `commands/agent.rs` `start_agent_session` | ACP 优先，失败回退 PTY |
| ACP 会话 | 工作台 | `acp.rs` `run_connection` | 握手、发送提示、处理流式更新 |
| PTY 会话 | 工作台 | `agent/mod.rs` `start_session` | 启动进程，收发终端数据 |
| 拦截危险命令 | 工作台确认条 | `acp.rs` `wait_for_permission`、`route_permission`；`engine/policy.rs` `evaluate` | 匹配规则，决定放行、等待或拒绝 |
| 人工裁决 | `views/Console.tsx` `resolve`、`views/Gate.tsx` | `commands/policy.rs` `gate_resolve_pending`；`acp.rs` `resolve_permission` | 回复 Agent，写入账本 |
| 修改策略 | `views/Gate.tsx` | `commands/policy.rs` `gate_set_policy_text`；`engine/policy.rs` `compile` | 校验后热更新 |
| 任务收尾 | `views/Tasks.tsx` | `engine/finalize.rs` `finalize_task` | 编译 Brief、ADR 和草案 |
| Review Brief | `views/Briefs.tsx` | `engine/brief.rs` `compile`、`collect_risks` | 汇总证据，识别风险 |
| ADR | `views/Adr.tsx` | `engine/adr.rs` `compile`、`export` | decision 事件转决策记录 |
| 追溯代码行 | `views/Blame.tsx` | `engine/blame.rs` `blame_line`、`scan_repo_commits` | 结合 git blame 和提交标记 |
| 记忆审阅 | `views/Memory.tsx` | `commands/skill.rs` `update_skill_status` | draft 转 active |
| 记忆召回 | `views/Console.tsx` | `engine/search.rs` | 加权打分，低于阈值不注入 |
| 失败去重 | `views/Memory.tsx` | `engine/normalize.rs` `normalize_and_sign`；`db/failure.rs` | 归一化后取签名 |
| 经验保鲜 | `views/Memory.tsx` | `engine/freshness.rs` `run_freshness_check` | 模型变化时降级 |
| 历史扫描 | `views/Memory.tsx` | `history/mod.rs`、`history/candidates.rs` | 只读解析，质量门后生成候选 |
| 接手包 | `views/Settings.tsx` | `handover/pack.rs`、`handover/unpack.rs` | 打包、解包 AHP |
| 工作区锁 | 启动会话时 | `db/agent.rs` `acquire_workspace_lock` | 防止并行写同一仓库 |
| 脱敏 | 记录落库前 | `engine/redact.rs` `redact` | 替换密钥 |
| 模型设置 | `views/Settings.tsx` | `commands/settings.rs` `set_settings`；`acp.rs` `codex_config` | 传入 Codex |
| 记忆演示 | `views/Demo.tsx` | `lib/demo.ts`（前端） | 纯状态机，不调用模型 |

## 5.3 编码规范

| 方面 | 规范 | 工具 |
|---|---|---|
| Rust 格式 | rustfmt 默认风格 | `cargo fmt --check` |
| Rust 静态分析 | Clippy，告警视为错误 | `cargo clippy -- -D warnings` |
| TypeScript | 严格模式，业务代码禁止 `any` | `tsc --noEmit`、ESLint |
| React | Hooks 规则 | `eslint-plugin-react-hooks` |
| 编辑器 | 统一缩进、编码、行尾 | `.editorconfig` |
| 提交信息 | `类型(范围): 说明` | 约定式提交 |

`too_many_arguments` 在 crate 级放行，因为 Tauri 命令的参数就是 IPC 契约字段。

## 5.6 现场演示脚本

演示前确认：`ael3.exe` 能启动，`codex login status` 显示已登录，已准备一个空的 Git 仓库。

**主线（约 5 分钟）：**

1. **新建任务**：填写目标“创建 hello.txt”和项目路径，展示记忆预览。
2. **工作台**：选择 Codex，启动，展示流式输出。写文件时终端出现“放行并留痕”。
3. **发送**：“请用 PowerShell 执行 Remove-Item -Recurse -Force victim”。确认条出现，**点“阻止”**，到文件管理器确认目录还在。
4. **安全页**：展示裁决账本，规则为 `destructive_fs`，决定方为人工。
5. **证据页**：展示 Review Brief 和决策记录。

**备用方案：** 模型不可用时，选择 PowerShell 会话走同样的流程，不消耗额度；或进入“体验记忆复用”交互演示。全部失败时播放录好的视频。

**可能的提问：**

| 问题 | 回答要点 |
|---|---|
| 程序架构？ | 前端 React，后端 Rust，通过 Tauri IPC 通信；后端分命令层、运行时、引擎、数据层；数据存 SQLite |
| 技术栈？ | Tauri 2、Rust、SQLite FTS5、React 19、TypeScript、xterm.js、Playwright、GitHub Actions |
| 拦截怎么实现？ | Codex 以 read-only 模式启动，写操作必须申请权限；`acp.rs` 的 `wait_for_permission` 收到请求，用 `policy.rs` 的正则判定，再按 `route_permission` 决定 |
| 为什么不用 PTY 拦截？ | PTY 只看得到从 AEL 输入的内容，看不到 Agent 内部执行的命令 |
| 普通操作每次都要点吗？ | 不用。未命中规则的工作区内操作自动放行并留痕 |
| 数据存在哪？ | 本机 `%USERPROFILE%\.ael\ael.db`，AEL 没有服务器 |
| 怎么测试的？ | 单元、集成、Playwright、真实桌面脚本和真实 Codex 五层，见第 7 章 |
| 最难的问题？ | 自动化测试全过，真实 Codex 却绕过了海关。原因是只测了 PowerShell 通道，靠真实环境测试才发现 |
