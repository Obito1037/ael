# 1 选题与 NABCD 模型

## 1.1 选题

**题目：AEL3，本地优先的 AI 编码治理工作台**

选题类型：任务书 2.4 自主选题。

AI 编码工具已经能直接改代码、跑命令，但使用者随之面临四个新问题：AI 执行了危险操作拦不住，出错后说不清是谁、为什么改的，同样的错会反复犯，换一个工具又要重讲一遍上下文。AEL3 不是又一个写代码的 AI，而是坐在开发者和 AI 之间的一层治理软件，让 AI 写代码的过程 **可控、可追责、可理解、可复用**。

这个选题和课程直接相关。《智能软件工程》第 1 章提出软件工程 3.0 以人机交互智能为常态，第 5 章讲 AI 辅助编程与代码审查；本项目解决的就是 AI 进入开发流程之后的工程管理问题。

## 1.2 NABCD

### N（Need，需求）

最重要的一条：**开发者把执行权交给 AI 之后，失去了对过程的掌控。**

具体表现为：

| 痛点 | 场景 |
|---|---|
| 管不住 | AI 可以直接执行 `rm -rf`、强制推送、删库语句，等人发现已经晚了 |
| 审不过来 | AI 一次改上千行，审查者只有 diff，看不到目标、决策和验证过程 |
| 追不到责 | 线上某一行出问题，只知道是 AI 写的，找不回当时的决策依据 |
| 记不住 | AI 换一个会话就忘了上次的教训，同样的错反复出现 |
| 换不动 | 换工具或换人接手时，上下文要从头讲一遍 |

第 5 章引用的 Stack Overflow 2023 调查显示，44% 的受访者已在日常开发中使用 AI，其中 83% 用于写代码。使用越普遍，这些问题越突出。

目标用户是个人开发者、使用 AI 编码工具的学生和小型开发团队。

### A（Approach，做法）

把 AI 的一次任务当作一条可记录、可裁决、可编译的证据链。

| 做法 | 解决的痛点 |
|---|---|
| **运行时海关**：AI 的写操作先过策略规则，危险命令扣下等人工裁决 | 管不住 |
| **Review Brief**：把证据链编译成一页摘要，包含目标、决策、已拦截错误、验证和风险 | 审不过来 |
| **Agent Blame**：提交时写入 `AEL-Task` 标记，从任意一行代码回到当时的任务和决策 | 追不到责 |
| **经验库与 Failure Guard**：任务收尾后沉淀经验和失败签名，新任务开始前自动提醒 | 记不住 |
| **AHP 接手包**：把任务、证据和约束打包，换工具或换人时直接接手 | 换不动 |

技术上采用本地优先架构：数据全部保存在本机 SQLite，不需要账号和服务器；通过 ACP 协议与 PTY 两种方式接入 Codex 等现有工具，不重新实现模型能力。

### B（Benefit，好处）

- **开发者**：可以放心把任务交给 AI，危险操作有人兜底，普通操作自动放行、不打断工作。
- **代码审查者**：先看一页证据，再决定细看哪里。
- **接手的人**：不用重新问一遍背景，从接手包开始工作。
- **隐私**：代码和对话记录不会上传到 AEL 的服务器，因为 AEL 没有服务器。

### C（Competitors，竞争）

| 类别 | 产品 | 能力 | 与 AEL3 的差异 |
|---|---|---|---|
| AI 编码工具自带审批 | Codex、Claude Code | 工具内部审批命令 | 只管自己；规则和记录分散在各工具中。本项目实测发现，Codex 适配器的默认模式由模型自行批准，删除目录时使用者收不到任何提示（见测试报告缺陷 D-06） |
| AI 代码审查 | GitHub Copilot Code Review | 在 PR 阶段给审查意见 | 只看结果，不记录过程；发生在执行之后，拦不住运行时操作 |
| 静态分析 | SonarQube | 扫描代码缺陷和规范问题 | 分析代码本身，不了解任务目标和 AI 的决策 |
| 版本控制 | `git blame` | 定位某行的提交 | 只能追到提交，追不到决策依据 |

AEL3 的定位是这些工具之间的连接层：不替代它们，而是在跨工具的层面统一治理和留痕。

**劣势也要承认：** 工具自带能力会持续增强；AEL3 依赖各工具的协议和本地记录格式，上游变化时需要跟进；目前只有 Codex 经过真实流程验证。

### D（Delivery，推广）

1. **开源分发**：代码公开在 GitHub，提供 Windows 安装包。
2. **从同学开始**：先在使用 AI 编程的同学中试用，用真实反馈迭代。
3. **绑定课程场景**：提供不消耗模型额度的演示流程（`scripts/verify-core-flow.mjs`）和内置交互演示，便于教学展示。
4. **开放标准**：AHP 接手包格式公开（`contracts/AHP-SPEC.md`），其他工具可以读写，降低使用门槛。

## 1.3 创新点

1. **运行时治理**：大多数方案在代码写完后才检查，AEL3 在命令执行前裁决。
2. **一条证据链，多种产物**：同一份任务记录编译出 Brief、ADR、经验和失败记录，不需要额外写文档。
3. **经验保鲜期**：模型换代时，旧经验自动降级为待重验（`engine/freshness.rs`），避免过时经验误导 AI。
4. **跨工具**：规则、记录和记忆不绑定任何一家 AI 工具。
